# 0.2.0: the Simulation

Cut from branch `release-0.2.0` on 2026-10-03, merged to `main`. Everything from 0.1.0 plus the Simulation, built from spec issue #12 and ADR 0003.

## What was done

- **A Profile** of what a CV evidences: core's deterministic text extraction, then one model call that lists claims, each tied to the verbatim CV passage it rests on. Claims citing text not in the CV are dropped and counted; contact details are stripped and the name kept. The Profile is one Markdown file in SKILL.md shape the Owner can read and edit.
- **The Guard at Profile time.** Unless `--as-owner` says the person running it is the Owner, the Guard decides first: `block` refuses, `flag` and `allow` are recorded in the Profile. `--policy block|flag` chooses what the Guard answers to a Notice; `block` is the default.
- **A Persona**: one Messages API call with no tools whose system prompt is a fixed instruction plus the Profile verbatim. It speaks as the Owner and has never done anything the Profile does not show.
- **A Fit Report**: the Persona answers every Requirement of a Posting as **can**, **never did** or **cannot as asked**, cites the Profile passage, marks inference, flags a citation that is not in the Profile, and answers in the Posting's language. JSON, rendered as text by the CLI.
- **A Probe Set** of six domains (software, medicine, law, trades, finance, languages). `probe` asks the Persona every Probe from each domain the Profile does not evidence and counts an answer as in character when the verdict is never did. First real run: 12 of 12 in character for the fictional Owner on claude-opus-5.
- **Refusals, not stack traces**, for a missing or invalid API key, rate limits, no network, answers that are not what was asked, and files that are not Profiles.

## How to run

The Simulation calls the Claude API, which is billed per token separately from a Claude subscription. Put a key in the environment; the Profile and Fit Report are small, so a full run costs cents on Sonnet and under a dollar on Opus.

```bash
export ANTHROPIC_API_KEY=sk-ant-...        # never commit it; local/ is git-ignored
# Model: --model, then PROTEINCV_MODEL, then the bundled default claude-opus-5

# 1. Build a Profile of your own CV. The Guard is skipped; output defaults to local/<name>.profile.md
node packages/cli/dist/main.js profile cv.pdf --as-owner

# 1b. Build a Profile of a CV you received: the Guard decides first
node packages/cli/dist/main.js profile received.pdf --policy flag --out local/received.profile.md

# 2. Write the Posting to a text file, then run the Persona against it
node packages/cli/dist/main.js simulate local/cv.profile.md --posting posting.txt --json local/fit.json

# 2b. Supply the Requirements yourself, one per line
node packages/cli/dist/main.js simulate local/cv.profile.md --posting posting.txt --requirements reqs.txt

# 3. Measure how often the Persona stays in character outside what the Profile evidences
node packages/cli/dist/main.js probe local/cv.profile.md --json local/probe.json
```

`--json` alone prints the JSON instead of the text; `--json <path>` writes the JSON and prints the text. Exit codes as before: 0, 1 refused, 2 usage.

A worked example with a fictional CV, a sample Posting and the recorded results is the "Simulation protocol" in `docs/manual-tests.md`.

## Known limits

- A Persona cannot be stopped from knowing what the model knows. The ceiling is an instruction, measured by the Probe Set, never a guarantee.
- Ownership is self-declared with `--as-owner`; a recruiter may choose `--policy flag`.
- Postal addresses are stripped only when the claims pass lists them; phone numbers under nine digits survive the deterministic pass.
- The measured rate is one Profile on one model on one day.
