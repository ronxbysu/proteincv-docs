# 0.6.5: Promo Codes, a link that gives away uses of Test fit and Protection

Cut from branch `release-0.6.5` on 2026-11-18. Someone who heard of ProteinCV from an Owner could not try it without an Account: a Guest protected one CV and nothing else. Now an Owner whose confirmed Account has an active Subscription can hand them a link that just works.

## What was done

- **Promo Codes.** A confirmed Account with an active Subscription, or an Admin, makes one on its account page, for Test fit, for Protection or for "All features", and copies its Promo Link, shown once. A code carries a number of uses, 10 by default, shared by everyone who has it, and expires after 30 days. The maker sees its codes with their uses left and can revoke one; it never sees who used them, and cannot use its own.
- **The link just works.** Opening a Promo Link makes nothing and spends nothing, so a chat app's preview costs no use. It lands on the feature's page with "Your Promo Code: 10 of 10 uses left, until 3 Nov." Whoever opened it protects CVs, or runs Test fit and gets the Fit Report, as a Guest, with no sign-up. A run that was refused or failed costs no use, and neither does a Test fit that only shows a report already made. A spent, an expired and a revoked code each say which; one whose maker deleted their Account says it is no longer valid, for good.
- **What a Guest makes with a code is kept**, for the Guest's 7 days: its Protected CVs with their files, and its Fit Reports as Past fits. After each use, the page offers to make an Account, which keeps them, with the code's remaining uses.
- **A code can also be typed in**, at sign-up or on the account page, or its link opened while signed in. An Account spends a code only on what it could not otherwise do: a confirmed Account's Test fits are free and never spend one.
- **The Admins' Promo Codes page** sets the uses per code, the days until a code expires and the live codes an Account may hold, and lists every code on the site with Revoke.
- **The Privacy page and the Terms** say what a Guest's files are and for how long, that a code is kept only as its hash, who may make codes, how one ends, and that codes may not be sold.

## Known limits

- **Every Test fit a code pays for costs the Operator at TypeSafe**, and a Promo Link lets someone with no confirmed email run one, by design. What can be out at one time is the live codes per Account × the uses per code × the Accounts with a Subscription, and an Admin's codes have no cap; a spent or expired code frees its place for another, so over time only TypeSafe's prepaid credit bounds the cost.
- **The count of uses under way is kept in memory**, so it holds for a site that runs in one process, as proteincv.com does. The last use still cannot be spent twice: that is decided in the database.
- **A Guest cannot delete a Protected CV it made with a code**: it has no Documents page, so the file stays until the Guest is deleted after its 7 days. It can delete its Past fits.
- **The home page does not mention Promo Links**, and its line that a Protected CV made as a guest is not kept is left as it was.
- The known limits of 0.6.4 stand.

## How to run

```bash
git checkout v0.6.5
corepack pnpm install
corepack pnpm -r build
corepack pnpm exec wrangler deploy
```

Three new tables (`promo_codes`, `promo_code_settings`, `promo_code_holdings`) and two new columns (`protected_cvs.promo_code_id`, `past_fits.promo_code_id`) are made at the site's first start, and the triggers `accounts_deleted` and `protected_cvs_made` are remade. Deleting an Account keeps the Promo Codes it made, ended, with no maker.
