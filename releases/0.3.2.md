# 0.3.2: the website in Docker

Cut from branch `release-0.3.2` on 2026-10-07. Everything from 0.3.1, now in a container. The website and a pinned Claude Code run in Docker on the Operator's own Claude subscription, with no API key. The website also reads the Notice on every CV it is given, and every Notice now ends with a rights line.

## What was done

### The website in Docker

- **`docker compose up --build`** serves the website on `127.0.0.1:8791`. The image carries the website and Claude Code 2.1.289, pinned, with its auto-updater off. Accounts and Profiles live in one volume, people's folders and run logs in another; both survive rebuilds.
- **Only the login is shared.** The container gets the Operator's Claude login, never the rest of their Claude folder, so Profile and Persona runs do not load the Operator's own instructions, plugins or hooks.
- **Three login routes.**
  - Route 1 mounts the machine's login file, so machine and container share one login (Windows, Linux).
  - Route 2 mounts it read-only and copies it in at start, for when route 1 fails.
  - Route 3 gives the container its own login in a volume. It is the way in on macOS, whose login sits in the Keychain.
- **A wrong login setup stops the site at start** with a message naming what to fix.
- **An optional Guard container** for the coming CV Store: `docker compose --profile guard up`, no published port, no Claude Code.
- **`pnpm docker:smoke`** checks both images locally without calling a model.
- **`DEPLOY.md`** walks a person through the deployment alone, step by step, with a check after each step and a troubleshooting table.

### The Notice on the website

- **Every uploaded CV goes through the Guard.** Until now the website built every Profile as the account holder's own, so someone else's Protected CV became a Profile with no word of the Owner's objection.
  - A Notice naming the account holder is their own: the Profile is built as theirs, and the page says the Notice was found.
  - A Notice naming anyone else is flagged: the profile page says that person does not consent to AI processing of the CV, and every verdict of its fit tests is marked "consent withheld".
- **The Notice no longer leaks into the Profile.** It was read as part of the CV, so a Persona could read the Owner's objection as its own words. The text the CV's Manifest records is taken out before the model reads the CV.
- **Every Notice ends with a rights line**: "Protected by ProteinCV (www.proteincv.com). © year Owner. All rights reserved." and a text and data mining reservation under Article 4(3) of Directive (EU) 2019/790, in English and Polish. Placeholder legal wording.

## How to run

See `DEPLOY.md` in the repository. In short, on Windows or Linux with Claude Code signed in:

```bash
cp .env.example .env     # set CLAUDE_CREDENTIALS to your .claude/.credentials.json
docker compose up -d --build
# http://localhost:8791
```

On macOS, follow route 3 in `DEPLOY.md`: a compose override, then one sign-in inside the container.

## Known limits

- Whether a Notice is "your own" is decided by comparing names the account holder types in; nothing proves who they are.
- A hand-written objection with no Owner name in it ("I do not consent to AI processing") is always flagged, even on the uploader's own CV.
- Only the Notice text a CV's Manifest records is taken out before the model reads it. A CV that lost its Manifest, for example by being printed to PDF again, still carries the hidden Notice into the Profile.
- The rights line and the GDPR appendix are placeholder legal wording, to be checked by a lawyer before a public release.
- Route 1 shares one live login between machine and container; whether a token refresh on one side signs the other out has not been seen yet.
- The VPS profile (`claude setup-token`, closed sign-up) is not built.
