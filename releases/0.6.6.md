# 0.6.6: My CVs, your CVs with their Versions

Cut from branch `release-0.6.6` on 2026-11-19. An Owner who signed in landed on Documents, a list of Protected CVs, and started every protect and every Test fit with a fresh upload: the site kept no original. Now an Owner keeps CVs, or any other PDF or Word documents, on the site, with each CV's Versions, and protects or tests one without finding the file again.

## What was done

- **My CVs**, first in the menu, where signing in and signing up land. A confirmed Account adds its CV there, a PDF or a Word document, checked as a protect upload is. Each CV has a name, which the Owner can change, and one or more Versions, v1, v2, …, each with its date and an optional note. A file whose text is already that of a live Version of the same CV is refused as "already here"; a removed one does not count.
- **Protect or test a Version.** "Protect" opens the protect choices with the Version chosen and the Notice defaults filled in; it takes the Free CV or a Subscription's place exactly as an upload does. "Test fit", where Test fit runs on the classifier, opens Fit Check with the Version chosen. The Protect and Fit Check pages also offer "CV from My CVs" beside the upload. A Protected CV or a Past fit made from a Version says so: "from Data engineer, EN, v3".
- **Uploads stay one-off** unless the Owner ticks "Also add to My CVs", on Protect or Fit Check. Ticked, the CV is added first; the same file, byte for byte, already a live Version in My CVs is used instead, and nothing new is added.
- **Remove hides, never deletes.** Removing a Version or a CV hides it and frees its place; its file is kept until the Account is deleted. Protected CVs and Past fits made from it stay, marked "(removed)". Deleting the Account deletes every CV file.
- **Limits**: 5 CVs per Account and 10 Versions per CV by default, on the Admins' new CV limits page. Storing CVs is free; keeping Protected CVs is still what a Subscription buys.
- **The home page, Privacy and Terms** now say the original is stored only when the Owner adds it to My CVs, kept until the Account is deleted, removed ones included; a one-off upload and a Guest's upload are not kept.
- Every new page was looked at in a browser at desktop and phone width.

## Known limits

- **No Restore.** A removed CV or Version cannot be brought back on the site, though its file is kept; an Operator could restore one by hand in the database.
- **Erasing one CV's file means deleting the Account.** Remove keeps the file, by the Owner's rule (ADR 0013). An erasure request for a single CV, without deleting the Account, needs an Operator step.
- **No API for CVs.** The API protects and tests uploads only.
- **Storage grows and does not shrink on Remove**: up to 50 files per confirmed Account at the defaults. The storage guard and the Admin limits bound it.
- **A Promo Code pays for nothing done on a stored CV**, including a ticked upload; untick the box to let a code pay for a one-off upload.
- **The Protect page lists only each CV's newest Version.** An older one is protected from its own "Protect" in My CVs.
- **Test fit on a Version runs only where Test fit runs on the classifier**, as on proteincv.com; a site with its own model tests from the skills Profile, which reads no CV.
- The known limits of 0.6.5 stand.

## How to run

```bash
git checkout v0.6.6
corepack pnpm install
corepack pnpm -r build
corepack pnpm exec wrangler deploy
```

Three new tables (`cvs`, `cv_versions`, `cv_settings`), two new columns (`protected_cvs.cv_version_id`, `past_fits.cv_version_id`) and a new trigger (`cv_versions_file_written`) are made at the site's first start, and the trigger `accounts_deleted` is remade. Version files go in the same file store as Protected CVs, under `versions/`.
