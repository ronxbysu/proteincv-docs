# 0.7.4: secrets that take effect

Cut from branch `release-0.7.4` on 2026-11-24. The Turnstile keys for 0.7.3's Free Test fit for Guests were set on 2026-11-23, but the feature stayed off: the site on Cloudflare reads its secrets only when it starts, and it never restarted. Neither setting the secrets, a deploy with the same image, nor ten idle minutes replaced it.

## What was done

- **The Worker restarts the site when its secrets changed.** It records a fingerprint of the settings the running site started with (a SHA-256, never a secret). When a request finds the Worker's settings differ, it stops the site and starts it again with the new ones; that request waits about as long as a wake from sleep. If the old site is still running 10 seconds after it was stopped, the request is told to try again, and the next one stops it again.
- **The site stops when told to.** It ran as its image's first process, which ignores a stop signal it has no handler for, so Cloudflare's signal to sleep after 10 minutes without a request did nothing. It now stops taking requests and exits once the open ones are answered, or after 10 seconds.
- **No more restart label.** The Dockerfile's `com.proteincv.restart` label, changed by hand after a rotated secret since 0.5.4, is gone; `wrangler secret put` is enough.

## Known limits

- **A request that comes while the site restarts waits for the start.** On Turso that is a few seconds, growing with the database.
- **The restart is checked only by tests with a stand-in for Cloudflare's container**, until it runs on proteincv.com.
- **Two Worker versions with different secrets live at once** (a gradual deployment) would keep restarting each other's site. proteincv.com deploys each version to all traffic at once.
- **The manual browser checks for the Free Test fit for Guests** in `docs/manual-tests.md` are still to run, now that the feature can be on.
- The known limits of 0.7.3 stand.

## How to run

```bash
git checkout v0.7.4
corepack pnpm install
corepack pnpm -r build
corepack pnpm exec wrangler deploy
```

The first request after the deploy restarts the site once.
