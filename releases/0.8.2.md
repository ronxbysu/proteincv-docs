# 0.8.2: Core Requirements and close substitutes

Cut from the `release-0.8.2` branch on 2026-11-26. 0.8.1's Related experience listed, under a requirement the CV does not plainly meet, every Skill name of the CV of the same kind as one the requirement asks for, so a CV whose main language is Java showed "Related in the CV: Java" under the Python requirement of a Python Developer's job description: a strong false positive for the one requirement the job is built around. A Fit Report now marks each requirement core, must-have or nice-to-have; under a Skill name the job is built around it shows a Skill name of the CV as related only when it is a close substitute; and a test can be Strict, or made without Related experience (spec #431, ADR 0018).

## What was done

- **Core Requirements** (#432). Every requirement is marked core, must-have or nice-to-have, on the Fit Report page, in its PDF, on a Batch fit's reports and in its PDF; the Batch fit's CSV counts the core requirements each CV does not plainly meet. The JSON download and the API's answer give `tier` per requirement, with `must_have` and `weight` as they were. A core requirement weighs 3, as a must-have does, except a nice-to-have that is core only because it asks a core Skill name, which still weighs 1: the Fit percentage does not move with Related experience (the Owner's decision Q20, #431). A Past fit of 0.8.1 says it was made before core Requirements existed, and asking the same CV and job description again runs a new test. The questions of core Skill names took the largest run to 917,334 input tokens (USD 0.0385 at the classifier's price, USD 0.39 at ProteinCV's default prices); the close-substitute check below takes it further.
- **Close substitutes for core Skill names** (#433). Under a Skill name the job is built around (a core Skill name), a related Skill name of the CV is shown only when the classifier also places the pair on its 10-level scale at "takes a few days" or "the same thing, or a drop-in replacement" with at least the Admin's close-substitute threshold, 0.3 by default: "Close substitute in the CV: MariaDB", at most 3, surest first. A related name that is not one reads, for an Owner or a Guest, "Same field, not a substitute: given Java, required Python", at most 3; for an Organisation member only "N related names were not close enough to show." Skill names that are not core keep "Related in the CV:" as in 0.8.1, and the check never changes a verdict, a weight or the Fit percentage. The scale is asked only of pairs already related whose asked name is core, in a second round, once ever per pair for the current model and question version: its ten answers are kept in the Pair cache, so a new threshold asks nothing again, and a Past fit keeps the threshold it was made under. The page, the PDF, the JSON download and the API's answer all show it; the JSON gives `close_substitute` per related name and `not_close_count` per requirement where the check applied, and an Organisation member's JSON holds no name of a pair that is not a close substitute. At the top of a report, only a requirement with a close substitute, or a related name the check does not apply to, counts in "N Requirements have something related in the CV."; a requirement that lists only names that are not close enough is listed and not counted, and a report with only those says "No Requirement has something related in the CV that is close enough to count.", then, for an Owner or a Guest, "The related names listed are of the same field as what is asked, not substitutes for it.", for an Organisation member "Related names were found, but none close enough to show; each Requirement says how many.", and never "Ask the candidate about it before deciding." (the review of #469). A Past fit made before it on this branch (question version 6) runs a new test. The largest run, which a Balance must hold before a run paid by its tokens starts, became 1,024,000 input tokens: USD 0.0430 at the classifier's price, USD 0.44 at ProteinCV's default prices (it was 832,000 in 0.8.1: USD 0.035 and USD 0.35); Strict takes it further (below).
- **Run options: Related experience and Strict** (#439, #434). The Fit Check page and the Batch fit form have two boxes, and the API two optional fields, `related` and `strict` (`true`, `false`, `1` or `0`). Related experience turned off looks for nothing related, and the report says "Related experience was not looked for: turned off for this run." **Strict** gives every Skill name a requirement asks the close-substitute check, not only a core one: a Strict report has no "Related in the CV:", only close substitutes and, for an Owner or a Guest, "Same field, not a substitute: given SQLite, required PostgreSQL", for an Organisation member only the count. Related experience is on by default for everyone; Strict is off for an Owner and a Guest and on for an Organisation member and an Organisation's API call. Neither option changes a verdict, a weight, a tier or the Fit percentage. A short explanation of a core Skill name, a close substitute and Strict sits beside the boxes, and the API page documents both fields. The browser remembers the last choice; there is no account setting. The home page's Test fit band, a Guest's form and a Promo Link's show no boxes and run with the defaults. A Past fit is shown again only under the same options, beside the thresholds and question versions, so other options run a new test; every Past fit made before Strict counts as made without it. With Related experience off, Strict changes nothing, so it is kept as off and the same Past fit is shown either way, with no second run to pay for (the Owner's decision Q25). For the same reason neither Related experience threshold is matched for a test without it: its Past fit keeps both as null, and the same test without Related experience still shows it after an Admin changed either threshold, with nothing sent (Q25 extended, the review of #469). Because Strict can ask many more pairs the close-substitute scale, its cap per run doubled from 240 to 480 pairs (the Owner's decision Q23), which is 10 requests instead of 5: the largest run, which a Balance must hold before a run paid by its tokens starts, is now **1,130,667 input tokens: USD 0.0475 at the classifier's price, USD 0.48 at ProteinCV's default prices** (it was 1,024,000: USD 0.0430 and USD 0.44). A typical run is unchanged.
- **What each option costs, on the Fit Check page** (#435, worded by #436). Under the price, the quote of a Test fit paid by its tokens has one short line per option, in the reader's currency: what the test costs with it instead of without it, the other option as chosen, and how many times the tokens. Before the form has a CV and a job description it says it of the largest test, "Related experience: up to CHF 0.38 instead of CHF 0.08 for the largest test (×5.9 the tokens)." at the default prices and an exchange rate near 0.79: 1,130,667 input tokens against 192,000 (USD 0.0475 against USD 0.0081 at the classifier's price; USD 0.48 against USD 0.10, the price per run, at ProteinCV's default prices, where the 192,000 tokens come to USD 0.081). Once the form has them (after a refusal, or beside "Run again anyway") it says it "for this test", worked out from them; the page has no script to work it out while a CV is chosen. When the money is the same either way, the line just says so: "Strict: no extra cost." (see Known limits), and for Related experience "no extra cost for this test.", "no extra cost: this test costs the price per run either way." or "less than a cent more for this test.". Why Strict adds nothing is said on the API page. A Subscriber reads that both options are included in the Subscriber price per run, and the Batch fit form that they are included in the Organisation price per run, with no token figure. A run that draws nothing (the Free Test fit, an Admin's, a Promo Code's) shows no price, as before. No price per run changed. **The largest run follows the options:** with Related experience off, the form's "at most", the Balance a run paid by its tokens must hold before it starts, and what a Test fit holds while it runs are the largest run without it, the verdicts' 192,000 input tokens (USD 0.0081 at the classifier's price, USD 0.081 at ProteinCV's default prices, so the price per run, USD 0.10, at the defaults), not 1,130,667 (USD 0.0475, USD 0.48); the same for an API call with `related` false, which the API page says. With Related experience on, Strict or not, it stays 1,130,667. The CV fit prices page shows both largest runs in each currency.
- **The pages say it** (#436). The home page, its FAQ, the CV fit page (`/cv-job-match`, its structured data included) and `llms.txt` say that each requirement is marked core, must-have or nice-to-have, that a requirement the job description presents as core or as a must-have counts three times a nice-to-have, what a close substitute is (the same thing under another name, or a few days to move to from it, such as MariaDB for MySQL, not Java for Python), what is shown of a related name that is not one (to an Owner, "not a substitute"; in an Organisation's report, a count), and the two options with their defaults; the example Fit Report marks its first requirement core. The Terms say the same in a paragraph, and that neither option changes the price per run or the Subscriber price per run. The Privacy page says a Past fit holds each requirement's tier, the close substitutes and the options it was run with. Wherever a page names what every test keeps, it now says "ProteinCV keeps the names of skills, tools and technologies it finds (such as MySQL), whether two such names are related, and how close a substitute one is for the other, shared by every test, never with the text they were found in or whose test it was."; so do the Organisation documents (Terms 5.3, DPA 2.4 and Annex 1, the candidate information, the record of processing). No page, PDF or API text names the classifier's brand. ADR 0018 records the decisions; ADR 0014, 0017 and 0011 have dated notes.
- **Link previews show Fit Check** (#460, the Owner's decision Q27 c). A page without a description of its own says "Check your CV or resume against a job description: which requirements it shows, which it misses, related experience it could name, and a Fit percentage.", and the preview image of a shared link (`og.png`, drawn from `packages/web/design/og.svg` by `scripts/og-image.sh`) says "Check your CV against a job description. Fit Check shows what it meets and misses." instead of describing the Notice. The signed-out Fit Check page (`/fit`) gives an absolute preview image and its own address, so a shared link to it shows the image.
- **Protection is off the public pages** (#461, the Owner's decision Q28). ProteinCV no longer sells Protection; proteincv.com, where CV fit runs on the classifier, is about CV fit, and its public pages say nothing else:
  - **The home page** lost the Notice mock and its lede, "Add a Notice for AI", "What a Protected CV carries", "Protect a CV in three steps, a minute", the Guest protect form, the real chats with Claude, ChatGPT and Grok, the Protection questions of its FAQ and the Protection limits. It has the Test fit hero, what a Test fit tells you with its three steps, CV fit's two limits, the Test fit FAQ, which now ends with "Is my CV kept?", and a closing call to Test fit. Its structured data offers Test fit only, with no Free CV, and its feature list names no Notice.
  - **The public menu** is CV fit, Limits and FAQ, whatever `PROTEINCV_SHOW_EVIDENCE` says, also on a Guest's pages; **the footer** links no Inspect tool and no Evidence page, on every page of the site.
  - **`/cv-job-match`** lost its "Add a Notice for AI" button; it and the home page no longer name "your Protected CVs" among the CVs a Test fit takes (an Account still can choose one).
  - **`/api`** documents CV fit only: no Protection section, no code only the protect call answers, each shared code said of CV fit alone, and the Subscription named as what makes a Prote Key, with its yearly price. The protect call still answers a Prote Key, as a test proves; a member's page still lists `fit_only`.
  - **The guide** (`/guide/ai-screening`) says how to object in writing only: no Protected CV, Notice, Footer or Evidence link, and its closing call is "Check your CV against a job description".
  - **The sign-in pages** list CV fit, Past fits and My CVs instead of the Notice, the Manifest and the Footer.
  - **`llms.txt`** says CV fit only and lists no guest protect, Inspect or Evidence page; **the sitemap** has neither `/inspect` nor `/evidence`. Both pages still answer by their address, linked from no public page, and say noindex (`X-Robots-Tag`).
  - **The Terms** lead "What ProteinCV does" with CV fit and no longer link the Evidence page; everything they say of Protection, the Free CV and what a Subscription buys stays, since an Account can still protect and existing Subscriptions bought it. **Privacy** is unchanged: it still says what is kept of Protected CVs.
  - ADR 0007 has a dated note. Every other site (one with its own model, or with neither) is as it was. Signed-in pages are not changed.
- **The Fit Check runs whole CV fits** (#454, Q26). `node packages/web/dist/fitCheckMain.js --end-to-end` runs nine pairs of a CV and a job description from the Fit Check Set through the engine a Test fit uses, on a throwaway store, once with core Skill names only, once Strict and once more on the warm Pair cache, and reports per pair the verdicts, the tiers, the core Skill names, the close substitutes and what was hidden, against the labels by the rule of days, with every token figure priced. `--dry-run` prints its bound: at most 558 requests and 10,384,095 input tokens for the three passes (USD 0.4361 at the classifier's price, USD 4.3613 at ProteinCV's default prices); a real run sends far less. Run on the real classifier on 2026-11-26: nine pairs in three passes, 176 requests, **478,601 input tokens: USD 0.0201 at the classifier's price, USD 0.20 at ProteinCV's default prices**, about 20,000 tokens a CV fit (USD 0.0008, USD 0.008 at ×10); every CV fit made a report. Core only 178,715 tokens (USD 0.0075, USD 0.075 at ×10), Strict 192,770 (USD 0.0081, USD 0.081), Strict again on the warm Pair cache 107,116 (USD 0.0045, USD 0.045): the cache held 562 of 624 `same_group` answers and 74 of 75 Scores and saved 85,654 tokens (USD 0.0036, USD 0.036 at ×10). Java, JavaScript and PHP under the core Python of a Python Developer's job description read "Same field, not a substitute"; MariaDB under the core MySQL of a MySQL administrator's is a close substitute and MongoDB is not; 35 of 36 labelled core Skill names agreed (36 of 37 under Strict), "fintech" called core as in Q19; Strict checked every Requirement that asks a Skill name (34 of 34, against 10 of 33). The bound was 10,384,095 tokens (USD 0.4361, USD 4.3613 at ×10).
- **CI runs on the Mac, through Docker** (#459, #463, #464), for the operator. `.github/workflows/ci.yml` sends every push to the self-hosted runner on the Owner's Mac (`runs-on: [self-hosted, macOS, proteincv-docker]`), whose one step is `bash scripts/ci-docker.sh "$GITHUB_SHA"`: the full suite (build, typecheck, test) in a `node:22-bookworm` container on a `git archive` of the pushed commit, committed files only. CI never runs on GitHub-hosted runners. While the Mac is off or asleep the `check` job waits in the queue, and `bash scripts/ci-docker.sh <ref>` runs the same by hand, ending with "CI on Docker: PASSED for <sha>". The deployment is unchanged.

## Known limits

- **Core Skill names miss the 1-in-20 rule, accepted as measured** (the Owner's decision Q19 a, 2026-11-26, #431). A Skill name is core when the classifier reads it as what the job is mainly about or as its main tool, and a requirement that asks one is core. On the measured set (2026-11-26, 20 requests, 62,111 input tokens: USD 0.0026 at the classifier's price, USD 0.0261 at ProteinCV's default prices) it found 14 of 17 core names, and called 3 of 58 names that are not core core ("Google Ads", "fintech", "finance"), over the 1 in 20 the rule allows; the rule stays recorded as missed. It missed Power BI, "paid search" and "variance analysis". A name wrongly read as core only makes the hints under its requirement stricter.
- **A requirement the CV plainly meets is core only when the job description says so, accepted** (the Owner's decision Q22, #431). Skill names are found only in the requirements the CV does not plainly meet, and only when Related experience is looked for, so "3+ years of Python" can be core in one CV's report and a must-have in another's, where the CV meets it. Turned off, not looked for or failed, every requirement is core only where the job description presents it as core, and the report says so.
- **At most 480 pairs a run are asked the close-substitute scale** (#433; 240 until #434, the Owner's decision Q23), about 200,000 input tokens of ordinary names (USD 0.0084 at the classifier's price, USD 0.084 at ProteinCV's default prices). A pair whose answer the Pair cache holds is not counted. Over the cap Related experience is not looked for, and the report says the CV and the job description are too large for it, as over the cap of pairs, never a part of the scale's questions; with core Skill names alone a run rarely comes near it, and a Strict run on a CV with many Skill names can.
- **Strict is quoted as adding nothing** (the Owner's decision Q24, #431; kept by #435). Which Skill names are core is known only once a run reads the job description, and any of them may be, so a test without Strict can ask every pair the close-substitute scale, as a Strict one does; ProteinCV has no cap on core Skill names that would bound it lower. So the Fit Check page's estimate, its "at most" and the Balance a run needs count the scale for every pair the estimate counts, up to the cap of 480 (about 200,000 input tokens of ordinary names: USD 0.0084 at the classifier's price, USD 0.084 at ProteinCV's default prices), Strict or not, and the page says "Strict: no extra cost.", the API page why. A quote can be higher than what the run draws, most for a test without Strict.
- **A nice-to-have that asks a core Skill name is marked core, and weighs 1.** The measurement called 2 of 23 labelled nice-to-haves core, among them "A degree in business or marketing is desirable." (through "marketing"); for those the look changes only the mark and the stricter hints, never the Fit percentage.
- **Skill names that are not names reach the report** (the 0.8.1 extraction limit, now more visible; to be fixed in 0.8.3). In the real end-to-end run a verb or a plain word read as a Skill name ("Develop" and "Design" read as core, "Write unit", "team", "production"), a company of the CV was paired ("Same field, not a substitute: given Pixelmill, required Design"), and a name came out with the words after it ("MariaDB clusters", "MongoDB replica set") where the Skill list does not hold it yet. They are hints, never counted, but an Owner reads them.
- **A Fit percentage can move a few points between two runs of the same CV and job description**: in the real run, 92% then 87% for one pair, as verdicts near the cut-off vary between the classifier's answers. The options never change it (Q20).
- **A Skill name can be read as something else**: Postman, the API tool, was placed on the lowest level for Insomnia, most likely read as the sleep disorder, so a close substitute was hidden.
- **Protection still answers where nothing links it** (#461). The Guest protect form at `/guest/protect`, the Inspect tool and the Evidence page answer by their address and still describe and offer Protection; the Evidence page's closing call sends to the home page's Guest form, which is gone. An Account's own pages still protect, and a Promo Code for Protection still works.
- **Nothing was checked by eye in a browser yet**: the Fit Report page with its tiers and three kinds of line, the Fit Check page's boxes and option lines, the PDF and the changed public pages were checked by the tests only.
- The known limits of 0.8.1 stand.
