# 0.2.1: the Installed Persona

Cut from branch `release-0.2.1` on 2026-10-03. Everything from 0.2.0 plus the folder flow: the Persona as a Claude Code skill in the person's own folder, run in the console on a Claude subscription, with no API key and no per-token cost.

## What was done

- **`skill`** writes the Installed Persona into a person's folder: `<folder>/.claude/skills/skill-<firstname-lastname>/SKILL.md`. It is the same system prompt `simulate` sends (the Persona instruction, the consent clause when the Profile is flagged, the Profile verbatim), followed by what the console needs: read the Posting file named by the argument, print the Fit Report JSON and a readable version, and carry the "Consent withheld." mark itself when the Profile is flagged, since no caller sets it there.
- **The run command is printed** by `skill`: a Claude Code session in that folder with project settings only and the Read tool, then `/skill-<name> posting.txt`. Two facts shaped it: `--bare` never reads OAuth or keychain credentials, so strict isolation is the API-key variant; and `--tools` takes every argument after it, so in print mode the prompt goes first.
- **Verified end to end** in a Claude Code 2.1.280 print-mode session on the fictional Owner: the Installed Persona was found from project settings alone, read the Posting with the Read tool, and printed the Fit Report. Recorded in the manual protocol.
- The Profile stays the editable source: build it with `profile`, edit it, install it with `skill`. The Probe Set stays on the API.

## How to run

```bash
# One folder per person, with their CV in it. Build the Profile first (see 0.2.0; this one call needs the API key).
node packages/cli/dist/main.js profile people/jane/cv.pdf --as-owner --out people/jane/jane.profile.md

# Install the Persona as that folder's Claude Code skill. No model call.
node packages/cli/dist/main.js skill people/jane/jane.profile.md --into people/jane

# Run it on your subscription: a session in the folder with project settings only and the Read tool
cd people/jane && claude --setting-sources project --tools Read
# then type:   /skill-jane-doe posting.txt

# Or in one go. Prompt first: --tools takes everything after it.
cd people/jane && claude -p "/skill-jane-doe posting.txt" --setting-sources project --tools Read

# Strict isolation, nothing but this folder loaded: bare mode, which needs ANTHROPIC_API_KEY and is billed per token
cd people/jane && claude --bare --add-dir . --tools Read
```

The console prints the Fit Report JSON, then one block per Requirement with the verdict, the answer and the passage it rests on.

## Known limits

- The same ceiling as 0.2.0: a Persona cannot be stopped from knowing what the model knows. A subscription session also sees any user-level skills you have installed; the Persona instruction does the isolating, and bare mode removes the rest at the cost of needing a key.
- Reinstalling overwrites the file. If the Owner's name in the Profile changed, the old `skill-<name>` folder stays until you remove it.
- The readable version in the console is written by the Persona, not by the CLI's renderer; the JSON above it is the exact Fit Report shape.
