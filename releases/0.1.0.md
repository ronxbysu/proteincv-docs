# 0.1.0: the Notice and the Guard

Tagged `v0.1.0` on 2026-10-03 from branch `release-0.1.0`. The first release: the writing side (core and CLI) and the reading side (the Guard).

## What was done

- **Protection Mode vsAI.** `protect` writes the Owner's Notice on every page in the PDF invisible render mode, so a Protected CV looks and prints like the original while any text-extraction pipeline reads the Notice first. A Manifest with the Owner, the Document ID, the mode, the language, the date and a fingerprint of the original is stored in the document.
- **Bundled Notice wording** in English and Polish, custom wording with `{owner}`, `{id}` and `{date}` placeholders, and an optional legal appendix (placeholder GDPR wording, not yet lawyer-reviewed).
- **Opt-in visible Footer** for readers that see pages as images, such as Gemini. Off by default because it changes the page's appearance.
- **Inspect**, which prints the Manifest and whether every page still carries the Notice.
- **Refusals** for encrypted, signed, unreadable and non-PDF input; image-only PDFs are allowed with a warning; protecting a Protected CV replaces the old Notice.
- **The Guard**, a pure module plus a thin HTTP service, answers for any document: `block`, `flag` or `allow`, from three signals (Manifest, Notice text, keyword). It stores nothing and vouches for nothing: a Notice is unauthenticated.
- **Manual tests** against Claude, ChatGPT and Gemini, recorded in `docs/manual-tests.md`. Claude surfaces the Notice unprompted; ChatGPT only when asked; Gemini never sees invisible text and needs the Footer.

## How to run

```bash
# Protect a CV. Output defaults to <name>.protected.pdf
node packages/cli/dist/main.js protect cv.pdf --owner "Jane Doe"

# Polish Notice with the EU GDPR appendix
node packages/cli/dist/main.js protect cv.pdf --owner "Jane Doe" --lang pl --legal

# Visible Footer for readers that see pages as images
node packages/cli/dist/main.js protect cv.pdf --owner "Jane Doe" --visible-footer

# Inspect: the Manifest and whether every page still carries the Notice
node packages/cli/dist/main.js inspect cv.protected.pdf

# The Guard as a service, on port 8790
node packages/guard-service/dist/main.js
curl -sS -F file=@cv.protected.pdf http://localhost:8790/v1/guard
```

Exit codes: 0 success, 1 refused (the message names the code), 2 usage error.

## Known limits

- Vision-based pipelines never see the invisible Notice; the Footer covers them at the cost of a visible line.
- Keyword parsers with no language model are unaffected.
- No model is forced to refuse; the realistic outcomes are disclosure to the human and a record that consent was withheld.
- Nothing binds a Notice to the Owner it names.
- The Guard has no authentication; run it on an internal network.
