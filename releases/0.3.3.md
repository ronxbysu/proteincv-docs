# 0.3.3: pages, accounts and Guests

Cut from branch `release-0.3.3` on 2026-10-08. The website gets a menu with a page for each part, works on a phone, keeps Protected CVs so they can be downloaded again, and lets a person protect one CV without an account.

**Before you upgrade, back up the database volume.** The first start changes the accounts table in a way that cannot be undone (see `DEPLOY.md`, "Back up and restore").

## What was done

### Pages and phones

- **A menu**: Profile, Protected CVs, Test fit, Test runs and Sign out. On a phone it folds into a **Menu** button that opens a panel; it needs no JavaScript.
- **A page for each part**, instead of one long page. Old links to Fit Reports and test runs still work.
- **Phone layout**: every page was measured at 360, 390 and 768 px wide, with no sideways scroll and tap targets at least 44 px; one email-change state was measured at 360 px only. Tables become one card per row on a phone.

### The Account

- **An edit page** for first and last name, email, and a "LinkedIn or other profile URL" that only you see. Change password and Delete account live there too.
- **Email confirmation**: a new account gets a link to confirm its email. Until then it can make one Protected CV. Accounts from earlier releases count as confirmed.
- **A changed email** takes effect only once the link sent to the new address is opened; the old address gets a note.

### Protected CVs

- **Download them again**: the protected PDF is now kept until you delete it, and its file name in the list is the download link. Your original CV is still never stored. CVs protected before 0.3.3 were not kept and say so.

### Guests

- **Protect one CV without an account**: upload it on the landing page with the name for the Notice, and download the Protected CV. Only one such Guest per IP address at a time.
- **Keep it**: confirm an email and choose a name and password, or sign in or sign up, and the CV moves into your account.
- **Or let it go**: a Guest that is never confirmed is deleted with its CV after 7 days.

## Known limits

- **One Guest at a time across the site** when it runs in Docker with published ports, as `DEPLOY.md` sets it up: the container sees every visitor at the same gateway address. Behind a reverse proxy, `PROTEINCV_TRUST_PROXY=1` uses the real address.
- A Guest cannot sign out.
- An unconfirmed account that deletes its one Protected CV can protect another.
- CVs protected before 0.3.3 were not kept and cannot be downloaded; protect them again.
- Confirmation emails were tested with a fake mail server only; no real email has been sent yet.

## How to run

See `DEPLOY.md` in the repository. To update a running deployment:

```bash
git fetch origin
git checkout v0.3.3
# back up the database volume first (DEPLOY.md, "Back up and restore")
docker compose up -d --build
```

Optional: set `SMTP_URL` in `.env` to send the confirmation emails (otherwise they are written to the container log), and `PROTEINCV_ORIGIN` to the address people open the site at.
