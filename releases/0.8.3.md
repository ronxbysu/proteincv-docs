# 0.8.3: The link preview image under a new address

Cut from `main` on 2026-11-27, as a hotfix to 0.8.2. 0.8.2 replaced the image a shared link to proteincv.com previews with. The new image says what Fit Check gives: "Check your CV against a job description. Fit Check shows what it meets and misses." But it kept the old image's address, `/og.png`. Chat apps and social sites keep an image by its address, often for days, so a link shared after 0.8.2 still previewed with 0.8.1's old image.

## What was done

- **The preview image has a new address, `/og-fit-check.png`**, which every page names in its `og:image` and `twitter:image`. An app that kept the old image has to fetch this one.
- **`/og.png` serves the same new image**, for a preview that still names the old address.
- **`scripts/og-image.sh` writes both files.** It says that a changed image needs a new name, and a test checks that no page names the old address.

## Known limits

- **A preview an app has already made for a link** can keep the old card until the app reads the page again. Most do so within a day or a week. Some refresh on demand: LinkedIn's Post Inspector, Facebook's Sharing Debugger, and Telegram's @WebpageBot. A new link, or the same link with something added such as `https://proteincv.com/?v=2`, previews afresh at once.
- The known limits of 0.8.2 stand.
