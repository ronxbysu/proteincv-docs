# 0.3.1: on the subscription

Cut from branch `release-0.3.1` on 2026-10-05. Everything from 0.3.0, and nothing needs an API key any more. The command line and the website build Profiles and run the Persona on a Claude subscription through Claude Code. On the website, you paste a job description, press **Test fit**, and the server runs your Persona as a Claude Code skill in your own folder, the folder flow from 0.2.1. Every test is logged with its whole conversation.

## What was done

### The command line

- **A subscription model client.** Each model call is one `claude -p` turn:
  - the request's system prompt replaces Claude Code's own, read from a file so a long Profile stays clear of command-line limits
  - the user message goes on stdin
  - it runs in safe mode with no tools, settings files, MCP servers, slash commands or saved session
  - the working folder is an empty temporary one, removed afterwards
- **No fallback to billing.** Every `ANTHROPIC_*` variable and every `CLAUDE_CODE_USE_*` switch is removed from the child's environment, so the call cannot use an API key, a proxy, or Bedrock, Vertex or Foundry. Checked by running `simulate` with a bogus key and an unreachable base URL set: it still answered on the subscription.
- **`--via claude-code`** is the new default for `profile`, `simulate` and `probe`. **`--via api`** keeps the Anthropic API, billed per token.
- **Verified** on the fictional Owner with no API key, Claude Code 2.1.289: a Profile of 28 claims, the Simulation passed, and the Probe Set stayed in character 12 of 12. Recorded in the manual protocol.
- ADR 0003 has an addendum. The Persona is still one call with the Profile as the system prompt; only the transport changed.

### The website: Job description to test your fit

- **The Persona card is now "Job description to test your fit"**, with a job description field and a **Test fit** button.
- **Test fit runs the Installed Persona in your folder.**
  1. The server writes your Profile as a Claude Code skill to `local/people/<account id>/.claude/skills/skill-<name>/SKILL.md`.
  2. It puts the job description in a one-off file beside the skill.
  3. It runs `/skill-<name> <file>` there with `claude -p --setting-sources project --tools Read`, the command `proteincv skill` prints.
  4. It reads the Fit Report JSON the skill prints.

  The job description file is removed when the test ends. Deleting your Profile or your account removes the folder.
- **Profiles are built on the subscription too.** The site's default, `PROTEINCV_VIA=claude-code`, needs no `ANTHROPIC_API_KEY`. `PROTEINCV_VIA=api` keeps the 0.3.0 API path.
- **Verified** in the site with no API key: the fictional Owner's Profile took 20 s to build (27 claims). Test fit on the protocol posting returned a Fit Report in 25 s with can, can, never did and cannot as asked. Afterwards the person's folder held only the skill.

### The run log

- **Every fit test is logged**, whether it worked or not, and listed under **Test runs** on the profile page: the job description's title, the start time, how long it took, tokens in and out, and ok or failed with the error.
- **Each run's page shows the numbers**:
  - when it ran and how long it took, the model, and the number of turns
  - the login Claude Code used: "Claude subscription" when it reports `apiKeySource: none`
  - input tokens (new, read from the cache and written to it) and output tokens
  - what the run would cost at API prices, marked as not billed on a subscription
  - the exit code and the exact command
- **And the whole conversation**: the prompt, the SKILL.md it loaded, then every message from Claude, each tool call with its input, each tool result, and how the session ended. The raw `stream-json` transcript downloads as JSONL.
- **The Test fit form says where your text goes**, and a test whose Profile was deleted or rebuilt while it ran keeps no Fit Report and no log.
- **The log is deleted with your Profile.** It holds the job description and your Profile, and the privacy page says so. The consent and privacy wording names the route the text takes: Claude Code on the subscription of whoever runs the server, or the Anthropic API when the site runs with `PROTEINCV_VIA=api`, which keeps no folder and no run log.
- **It paid off at once.** The first logged run showed Claude looking for the job description file in the skill's folder, failing, and finding it on a second read. The prompt now passes the file's absolute path; the same test went from 40.2 s to 28.7 s with one read.

## How to run

```bash
# Claude Code installed and signed in to your subscription. No API key.
corepack pnpm -r build

# The command line
node packages/cli/dist/main.js profile my-cv.pdf --as-owner --out local/me.profile.md
node packages/cli/dist/main.js simulate local/me.profile.md --posting posting.txt
node packages/cli/dist/main.js probe local/me.profile.md

# The website: http://localhost:8791, then sign up, build your Profile, paste a job description and press Test fit
node packages/web/dist/main.js
```

The Installed Persona from 0.2.1 still works for running the Persona yourself in an interactive session.

## Known limits

- The website runs on the subscription of whoever started it, which suits one person running the site for themselves. A site that serves other people should use `PROTEINCV_VIA=api` and an API key.
- A fit test takes 20 to 60 seconds. A `claude` process that runs for more than ten minutes is stopped, with every process it started, and the request is refused with that reason; the run log keeps what it printed.
- The posting file's path goes to the skill in double quotes. That was checked on macOS with a space in the folder name, not yet on Windows.
- A fit test's session also sees any user-level skills installed for Claude Code on the server; the run log lists them. The Persona instruction does the isolating, as in 0.2.1.
- On Windows, `claude` must be the native `claude.exe`; an npm `claude.cmd` shim is not started without a shell.
- Organisation-managed Claude Code settings still apply. The website's run log shows which login a fit test used; the command line does not report it.
